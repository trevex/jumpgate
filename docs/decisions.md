# Key decisions

The load-bearing architecture decisions and why we made them. Update this page
when a decision changes or a new one is made.

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Backend split | Go control plane + Rust data plane | Go wins the k8s operator ecosystem, ReBAC engines, enterprise SSO, and team velocity; Rust wins proxy performance/safety and is uniquely strong for future RDP (IronRDP). |
| Data-plane shape | Two-tier: thin gateway + per-protocol workers | Independent per-protocol scaling and per-protocol *language* freedom (a future worker can be Go) behind one protocol-agnostic gateway. |
| Proxy posture | Agentless L7 gateway | Lowest adoption friction; best fit for the JIT / data-protection story. No software on targets. |
| Auth interaction | "Approach A" — control plane brokers, workers enforce | Security-critical state stays centralized in Go; workers are stateless and hold secrets only for a live session; revocation is immediate. |
| Access model | Custom Role + RoleBinding (relationship-based, resolved in-engine) | Enterprise-grade custom roles; the relationship graph handles nested groups + folder inheritance, the control plane resolves roles → a fixed capability vocabulary. See the Authz-engine row for the backend. |
| Role model | explicit ReBAC-light userset-rewrite (fixed types, user-definable roles + rewrite rules); HoldsRole recursive CTE; folder cascade of standing access is explicit (a declared `parent` rule), no implicit cascade | Flexible role composition + folder cascade without OpenFGA's arbitrary-type generality; easy to reason about (ExplainRole shows the chain). |
| Discoverability | Permission-gated (Active ∪ Requestable) + 404-not-403 | Least privilege / need-to-know; asset existence is never leaked to unauthorized users. Requestable is now rule-based (a RequestPolicy the caller is eligible for), not a per-subject binding. |
| Catalog visibility | Server-computed via the Authorizer; CodeNotFound for invisible assets | Discovery is permission-gated; asset existence never leaks to unauthorized users. |
| Postgres escalation | Inline per-statement approval + time-boxed tiered step-up | "Access when you need it" done robustly on a structured protocol; DB-enforced via `SET ROLE` (defense in depth). |
| SSH escalation | Pre-session only | Parsing commands from an interactive TTY is not a robust enforcement boundary; keep it honest. |
| Session token | PASETO v4.public (ed25519) | Simpler and more misuse-resistant than JWT. |
| Identity (MVP) | Local accounts first | Fastest to iterate; OIDC/SAML/SCIM is a later sub-project. |
| User deactivation | `users.deactivated_at`; enforced at **Login** (no new token) **and** the auth **interceptor** (any authenticated RPC → `Unauthenticated`) | Immediate, revocable off-switch for a principal without deleting bindings/history. Residual: a deactivated user still *counts* in others' authz sets until their bindings are removed or the account is deleted — full exclusion (a `deactivated_at IS NULL` filter in the HoldsRole/approver/requester CTEs) is deferred. See [security.md](security.md#account-deactivation). |
| Authz engine | `Authorizer` seam + roll-our-own Postgres/recursive-CTE backend (M2a) | Our model (nested groups, explicit role-rewrite folder cascade, Active/Requestable tiers) maps cleanly to recursive SQL CTEs; avoids OpenFGA's heavy in-process footprint (~59 deps, separate store). OpenFGA (embedded or sidecar) remains a drop-in behind the seam. |
| Data layer | sqlc + pgx/v5 + goose (embedded migrations) | Type-safe SQL without ORM magic; migrations embedded in the binary; tests run against an ephemeral Postgres (initdb/pg_ctl), no Docker. |
| API layer | ConnectRPC (connect-go) over buf; opaque DB-backed bearer tokens | One proto contract for browser + CLI + future Rust gRPC workers, no Envoy; protovalidate for validation; CodeNotFound hides non-visible resources; tokens are revocable server-side (not JWT). |
| CLI language | Go (cobra) | Shares the API client; clean static cross-compiles. |
| Frontend | React + Vite SPA embedded in the backend binary | Matches the Teleport/hoop pattern; largest ecosystem for data-heavy admin UIs. |
| Dev environment | Nix flake devshell + direnv | One pinned, reproducible toolchain across contributors and CI. |
| Audit integrity | Hash-chained append-only log | Tamper-evident; standard, auditor-accepted mechanism. |
| Request policy (requestability + approval) | One `request_policies` row per (role, scope): its **existence ⇒ the role is requestable** there. Rule-based eligibility — requester = holders of `requester_role` on the scope ∪ explicit `requester` subjects (NOT per-subject `requestable` bindings, which are removed); approver = holders of `approver_role` ∪ explicit `approver` subjects; role-level default + per-scope override, most-specific wins; no policy ⇒ not requestable. `role_bindings` are **standing-only**. | Unifies "who may request" and "who approves" in one rule that composes with the role-rewrite graph (`HoldsRole`) instead of a subject-scoped binding; the gate travels with the role; folder vs asset are distinct scope flows; no org/manager graph dependency. |
| Service layout (Access-Model v2) | Four ConnectRPC services: **IdentityService** (users/groups/memberships/lifecycle), **CatalogService** (folders/assets + user-facing discovery), **AccessService** (all admin authz config: roles, role_grants, role_bindings, request_policies + subjects, ExplainRole), **AccessRequestService** (JIT runtime: ResolveApproval + the full RequestAccess/Approve/Deny/Cancel/Revoke + grants + reaper lifecycle, M3c) | Clean boundaries: *how access is defined* (static, admin — AccessService) vs *how it is obtained* (dynamic, user + approver — AccessRequestService); catalog no longer conflates the resource tree with the whole RBAC model. |
| JIT grant model (M3c) | An approved (or self-service, `required_approvals=0`) request mints a **time-boxed `access_grants` row** (role for a user at an asset scope, with `expires_at`); the authorizer's held-closure base is **`role_bindings` ∪ active `access_grants`**, so a grant flows through the role-rewrite graph exactly like a standing binding and stops the instant it expires/is revoked. **Grants≠governance:** the requester/approver predicates resolve **standing-only** (`HoldsRoleStanding`), so a JIT-granted role never lets you request or approve further. Revocation = **expiry** (background reaper, `ReaperInterval` 30s) **· manual `RevokeGrant`** (admin · the subject/self-revoke · a standing approver for its (role,asset)) **· deactivation** (revokes the user's active grants). Every revoke/expiry audits + calls a **`GrantTerminator` seam** (no-op now; real gateway session-kill is **M4**). Duration is clamped to `min(requested, policy.max_duration, MaxGrantTTL=8h)`, snapshotted at request time. | One primitive for every time-boxed elevation (SSH grant, future PG step-up); grants join authz without mutating admin config (`role_bindings` stay standing-only); grants≠governance prevents self-escalation loops; symmetric approve/revoke authority; expiry is correct even without the reaper (the `expires_at > now()` filter), so the reaper is a side-effects (audit + teardown) job. |

## Notable non-choices (deferred by design)

- **RDP, Kubernetes, MySQL/Mongo, HTTP/API proxying** — later sub-projects; the
  two-tier data plane is designed so each is an additive worker.
- **Inline DLP / command blocking** and **AI-agent/MCP governance** — differentiation
  bets deferred until the core is proven.
- **HA / multi-region** — out of MVP scope.
